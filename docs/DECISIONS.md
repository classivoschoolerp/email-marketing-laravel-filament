# Design decisions

Design decisions taken while building the platform. Each records the choice made where the
specification allowed more than one option. Every default is reversible.

| D-115 | Panel auth middleware must be PERSISTENT | Filament applies panel middleware to panel ROUTES only, but every Filament form submits to POST /livewire/update, which is not a panel route. Without `isPersistent: true` on `authMiddleware()`, `SetCurrentCustomer` never runs on the request that WRITES the row, so `CurrentCustomer` is empty and `BelongsToCustomer` stores `customer_id = NULL` - the record saves, then vanishes behind the tenant scope (404s, absent from lists). `Livewire::test()` cannot catch this: it never crosses the HTTP boundary, and in-process tests also leak the scoped tenant from the preceding GET, so the regression test calls `forgetScopedInstances()` between GET and POST. Same root cause family as the login 419: a panel-scoped concern that does not survive the Livewire round-trip | found in browser testing (post-Phase-3) |
